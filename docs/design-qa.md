## 반복 검수 결과

1. 1차 구현에서 Y축 레이블과 축 눈금이 겹치고 이벤트 영역이 지나치게 낮은 문제를 발견했다.
2. 차트 그리드 여백, 이벤트 행 높이, 선택 시점 값, 원인 카드 간격을 조정했다.
3. 긴 마크라인 숫자 레이블을 제거하고, 센서 범례와 온도 설정값 시리즈를 보강했다.
4. 우측 원인 레일의 글자 위계, 안전 상태, 주 행동 버튼을 시안과 같은 수준으로 정리했다.

## 필수 충실도 점검

- 타이포그래피: 설비 코드와 시각은 고정폭 글꼴, 제목과 본문은 가독성 중심 산세리프를 적용했다.
- 간격과 정렬: 세로 구분선, 카드 패딩, 차트 트랙, 이벤트 기준선을 1440px 기준으로 비교했다.
- 색상: 청색을 선택과 조치, 보라색을 결함 신호, 적색을 복합 이상, 녹색을 정상 스트림에 일관되게 사용했다.
- 아이콘과 자산: 별도 브랜드 자산을 복제하지 않고 Phosphor 아이콘에서 의미가 가장 가까운 형태를 선택했다.
- 문구와 숫자: 정적 시안의 정보 구조를 유지하되, 구현 화면의 시각과 센서값은 합성 스트림의 실제 상태를 표시한다.

## 상호작용과 런타임 점검

- 개요 화면에서 이상 설비를 선택해 진단 화면으로 이동했다.
- 설비 ID 검색과 상태 필터, 이벤트 유형 필터, 전체 근거 펼치기가 실제 목록을 바꾸는지 확인했다.
- 역할을 라인 엔지니어와 교대 관리자로 전환해 역할별 행동을 확인했다.
- 담당자를 지정하고 안전 조건 세 가지를 확인한 뒤 작업 지시 상태와 완료 기한을 확인했다.
- 다이얼로그의 포커스 순환과 닫은 뒤 이전 버튼으로 돌아가는 동작을 확인했다.
- 1280×720, 1024×768, 700×800에서 가로 잘림 없이 2열과 1열로 재배치되는지 확인했다.
- 마지막 깨끗한 브라우저 세션에서 경고와 오류 로그 0건, Vite 오류 오버레이 없음, WebSocket `데이터 수신 정상` 상태를 확인했다.

## 허용한 차이

- 합성 스트림은 실행 시점마다 이동하므로 시안과 타임스탬프, 이벤트의 가로 위치가 다르다.
- 제조사 전용 픽토그램 대신 의미가 가까운 오픈 아이콘을 사용했다.
- 구현 문구는 제조 현장 용어와 사용자의 다음 행동이 분명하도록 다듬어 정적 시안의 일부 표현과 다르다.

이 차이들은 기능과 정보 위계를 훼손하지 않는 P3 수준의 의도된 차이이며, 수정이 필요한 P0, P1, P2 항목은 남아 있지 않다.
