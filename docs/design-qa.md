# 디자인 검수 기록

초기 시안 비교 기록과 첫 번째 헤더 및 반응형 개선 기록을 보관한다. 아래의 통과 결과와 이미지는 각 검수 당시의 상태이며, 이후 변경까지 소급해 보증하지 않는다. 진단 UI의 후속 검토는 [전체 UI/UX 검토](./UI_UX_REVIEW_2026-08-31.md), 다섯 메뉴의 최초 구현은 [운영 기능 확장 기록](./OPERATIONS_MODULES_2026-08-31.md), 업무 화면 후속 수정은 [운영 화면 재검토](./OPERATIONS_UI_UX_REVIEW_2026-08-31.md), 현재 검증 상태는 [릴리스 검증 기록](./RELEASE_REVIEW_2026-08-31.md)을 기준으로 한다.

## 반복 검수 결과

1. 1차 구현에서 Y축 레이블과 축 눈금이 겹치고 이벤트 영역이 지나치게 낮은 문제를 발견했다.
2. 차트 그리드 여백, 이벤트 행 높이, 선택 시점 값, 원인 카드 간격을 조정했다.
3. 긴 마크라인 숫자 레이블을 제거하고, 센서 범례와 온도 설정값 시리즈를 보강했다.
4. 우측 원인 레일의 글자 위계, 안전 상태, 주 행동 버튼을 시안과 같은 수준으로 정리했다.

## 필수 충실도 점검

- 타이포그래피: 설비 코드와 시각은 고정폭 글꼴, 제목과 본문은 가독성 중심 산세리프를 적용했다.
- 간격과 정렬: 세로 구분선, 카드 패딩, 차트 트랙, 이벤트 기준선을 1440px 기준으로 비교했다.
- 색상: 청색을 선택과 조치, 보라색을 결함 신호, 적색을 복합 이상, 녹색을 정상 스트림에 일관되게 사용했다.
- 아이콘과 자산: 별도 브랜드 자산을 복제하지 않고 Phosphor 아이콘에서 의미가 가장 가까운 형태를 선택했다.
- 문구와 숫자: 정적 시안의 정보 구조를 유지하되, 구현 화면의 시각과 센서값은 합성 스트림의 실제 상태를 표시한다.

## 상호작용과 런타임 점검

- 개요 화면에서 이상 설비를 선택해 진단 화면으로 이동했다.
- 설비 ID 검색과 상태 필터, 이벤트 유형 필터, 전체 근거 펼치기가 실제 목록을 바꾸는지 확인했다.
- 역할을 라인 엔지니어와 교대 관리자로 전환해 역할별 버튼과 작업 지시 입력 권한을 확인했다.
- 라인 엔지니어에게는 기본 담당자가 고정되고, 교대 관리자에게만 담당자 선택 항목이 표시되는지 확인했다.
- 안전 조건 세 가지를 확인한 뒤 작업 지시 상태와 완료 기한을 확인했다.
- 다이얼로그의 포커스 순환과 닫은 뒤 이전 버튼으로 돌아가는 동작을 확인했다.
- 1280×720, 1024×768, 700×800에서 가로 잘림 없이 2열과 1열로 재배치되는지 확인했다.
- 마지막 깨끗한 브라우저 세션에서 경고와 오류 로그 0건, Vite 오류 오버레이 없음, WebSocket `데이터 수신 정상` 상태를 확인했다.

## 운영 실패 상태 재검수

2026년 8월 30일 이력 API 요청을 브라우저에서 강제로 차단해 다음 항목을 확인했다.

- 차트 상단에 실패 범위와 `이력 다시 불러오기`가 표시된다.
- 우측 신뢰도는 숫자 대신 `분석 보류`로 전환된다.
- 원인 후보는 `이력 미확인, 참고용`으로 표시되고 시각적 강조가 낮아진다.
- `이력 복구 후 진행` 버튼은 비활성화되어 작업 지시를 발행할 수 없다.
- 요청 차단을 해제하고 화면의 재시도 버튼을 누르면 경고가 사라지고 `92%` 신뢰도와 `현장 검증 시작` 버튼이 복구된다.
- 복구 후 화면 본문과 주요 인터랙션이 렌더링되며 Vite 오류 오버레이와 브라우저 런타임 오류가 없다.

## 허용한 차이

- 합성 스트림은 실행 시점마다 이동하므로 시안과 타임스탬프, 이벤트의 가로 위치가 다르다.
- 제조사 전용 픽토그램 대신 의미가 가까운 오픈 아이콘을 사용했다.
- 구현 문구는 제조 현장 용어와 사용자의 다음 행동이 분명하도록 다듬어 정적 시안의 일부 표현과 다르다.
- 헤더의 화면 이동 링크는 클릭 여부를 명확하게 구분하기 위해 초기 시안의 구분선 형태에서 테두리와 배경이 있는 버튼형 링크로 변경했다.

## 2026년 8월 31일 첫 번째 UI 회귀 검수

사용자가 제공한 권장 조치 카드와 헤더 스크린샷을 기준으로 로컬 화면을 재현하고, 공정 개요와 신호 분석 화면의 유사한 문제를 확인했다.

1. **권장 조치 — 통과:** 상태 배지와 설명을 세로로 분리하고 `white-space: nowrap`을 제거했다. 설명과 공통 버튼 라벨은 내용에 맞춰 줄바꿈되며, 분석 대기 및 이력 복구 상태에서도 카드 밖으로 넘치지 않는다.
2. **헤더 — 통과:** 공장과 라인 정보는 비상호작용 정보로 묶고, 화면 이동 링크에는 44px 클릭 영역, 테두리, 배경, 현재 화면 표시와 키보드 포커스를 적용했다. 모바일에서도 메뉴 이름과 데이터 수신 상태를 숨기지 않는다. 역할 선택은 컨트롤 전체 영역으로 조작할 수 있다.
3. **반응형 경계 — 통과:** 701px 부근의 좁은 진단 영역에서는 공정 단계와 도구 모음이 각 영역 안에서 가로 스크롤된다. 모바일 공정 개요의 스크린리더용 텍스트는 해당 탐색 항목 안에 위치시켜 페이지 전체의 가로 넘침을 방지했다.

자동 검증은 `apps/web/e2e/responsive-layout.spec.ts`에서 수행한다.

- 화면 너비: 1920, 1440, 1366, 1280, 1180, 1024, 1000, 821, 820, 701, 700, 521, 520, 390, 320 CSS px. 두 화면에서 총 30개 레이아웃을 확인했다.
- 교대 관리자 버튼 문구, 320px 이력 오류 배너와 비활성 조치, 검증 다이얼로그의 가로 넘침을 확인했다.
- 320px에서 메뉴 이름 노출, 키보드 Enter 이동, 현재 화면의 `aria-current`, 포커스 표시, 역할 변경과 검증 다이얼로그 진입을 확인했다.
- 기존 정상 작업 발행과 이력 장애 복구를 포함해 Chromium E2E 6개가 통과했다. Lint, TypeScript, 웹 21개와 서버 8개 테스트, 배포용 빌드, Storybook 빌드도 통과했다.
- 로컬 브라우저 콘솔 오류와 Vite 오류 오버레이는 없었다. E2E 종료 과정의 Vite WebSocket 프록시 `EPIPE`와 Storybook의 개발용 번들 크기 경고는 남아 있으며, 테스트와 빌드는 정상 종료했다.

가로 넘침 검사는 의도한 내부 스크롤 영역을 제외한다. 실제 브라우저 확대, 화면 낭독기, Safari 및 Firefox의 모든 동작이나 전체 WCAG 준수를 검증한 것은 아니다. 캡처는 로컬 `artifacts/ui-audit/`에 보관하며 저장소에는 포함하지 않는다.

위 차이는 기능과 정보 위계를 훼손하지 않는 의도된 차이입니다. 이 기록의 통과 결과는 명시한 뷰포트와 정상 및 이력 장애 시나리오에 한정하며, 실제 현장 데이터와 네트워크 조건의 무결성을 보증하지 않습니다.

이전 검수 결과: 명시한 범위에서 통과. 최신 전체 검수의 상태는 위에 연결한 별도 기록을 따른다.
