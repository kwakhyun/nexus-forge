# 전체 UI/UX 검토 기록 — 2026년 8월 31일

후속 변경: 아래의 COATER-02 전용 범위는 당시 기록이다. 현재는 [DRYER-02 재사용 구성](./EQUIPMENT_REUSE.md)을 추가했으며 최신 검증은 제출 준비 문서를 따른다.

이 문서는 다섯 운영 메뉴를 확장하기 전의 진단 UI 검토와 당시 실행 결과를 보존한 기록이다. 메뉴의 최초 구현은 [운영 기능 확장 기록](./OPERATIONS_MODULES_2026-08-31.md), 이후 업무 화면 수정은 [운영 화면 재검토](./OPERATIONS_UI_UX_REVIEW_2026-08-31.md), 최신 검증 상태는 [제출 준비 기록](./SUBMISSION_REVIEW_2026-08-31.md)을 따른다. 아래의 테스트 개수와 탭 메모리 한계는 해당 검토 시점의 상태다.

## 검토 대상과 상태

대상은 NEXUS Forge 공개 데모의 공정 개요, 신호 분석, 현장 검증 다이얼로그와 이들 사이의 핵심 흐름이다. 라인 엔지니어와 교대 관리자 역할, 좁은 너비와 낮은 높이, 키보드 조작, 로딩 및 실패 상태까지 포함했다. 단순한 정상 화면 캡처에 그치지 않고 데이터 누락, 응답 유실, 화면 이동 후 상태 유지도 점검했다.

이 기록은 **로컬 작업 트리의 수정 사항**을 설명한다. 이번 검토에서 커밋, 푸시, 공개 배포는 수행하지 않았다. 8월 31일 마지막 일괄 실행에서 자동 검증은 모두 통과했다. 앱 브라우저 정책으로 차단된 최종 시각 재검수는 통과로 표시하지 않는다.

## 수정한 주요 문제

### 판단과 작업 흐름

- **P1 — 미지원 설비의 잘못된 데이터 표시:** 라우트와 서버 이력 API가 COATER-02만 허용하도록 했다. 임의 설비 ID에 같은 데이터를 반환하지 않는다.
- **P1 — 중복 발행과 응답 유실:** 요청 중 닫기와 입력 변경을 차단하고, 미확인 요청을 화면 이동 후에도 보관한다. 서버는 같은 ID와 본문의 재시도를 동일 기록으로 응답한다. 단일 인스턴스 메모리에 한정된 보장이라는 한계를 명시한다.
- **P1 — 불완전한 데이터로 조치 진행:** 이력 조회 실패, 센서 수신 지연, 공정 현황 지연, 이상 시점 이력 누락, 가동 중 점검 불가 상태에서 새 작업 발행을 보류한다. 이미 발행한 결과 조회는 계속 허용한다.
- **P1 — 복구 경로 없는 화면 실패:** API 오류와 비정상 응답에 재시도를 제공하고, 화면 렌더링 오류 후에는 다른 화면으로 이동하거나 초기화 안내를 읽고 다시 불러올 수 있게 했다.
- **P1 — 실제 근거와 다른 수치:** 누락된 실시간 값의 대체 숫자와 다운샘플 결과에 따라 달라지던 참고값을 제거했다. 참고값은 이상 시점 근처의 원본에서만 선택한다.

### 레이아웃과 조작성

- **P2 — 좁은 권장 조치 카드의 텍스트 넘침:** 배지와 설명을 분리하고 공통 버튼과 긴 내용의 줄바꿈을 허용했다.
- **P2 — 헤더 클릭 가능 여부 불명확:** 공장/라인 정보와 화면 이동 버튼을 구분했다. 현재 화면 표시, 충분한 조작 영역, 키보드 포커스를 적용하고 모바일에서도 메뉴 이름을 유지했다.
- **P2 — 낮은 화면의 차트와 이벤트 잘림:** 내용 최소 높이와 내부 스크롤을 조정하고 영역 이동 링크를 추가했다. 짧은 모달에도 체크리스트와 발행 버튼이 도달 가능하다.
- **P2 — 차트 위 수치가 그래프를 가림:** 참고값을 별도 설명 목록으로 분리하고, 작은 차트에는 패널 제목과 축 여백을 재배치했다. 차트 툴팁은 영역 밖으로 나가지 않는다.
- **P2 — 차트 상호작용 초기화:** 구간 고정, 확대/이동, 범례 선택을 실시간 데이터 갱신 후에도 유지한다. 보관 이력을 벗어난 구간은 유효 범위로 보정하고 이를 안내한다. 일반 휠 스크롤은 페이지 이동을 방해하지 않는다.
- **P2 — 검색과 포커스 유실:** 접힌 그룹에서도 검색 결과가 보인다. 조건 초기화를 제공하고 목록 펼치기/접기 후 적절한 컨트롤로 포커스를 옮긴다.
- **P2 — 모바일 공정 단계에 키보드 진입 불가:** 가로 스크롤 영역에 포커스를 제공하고, 방향키로 숨은 공정까지 이동하는 동작을 회귀 검사한다.
- **P2 — 상태와 범위 오인:** 미제공 메뉴와 읽기 전용 설비를 구분한다. 공개 데모, 가상 분석, 작업 미전송, 보관 한계를 화면에 표시한다.
- **P2 — 안내 문구 대비:** 자동 접근성 검사에서 발견한 비활성 메뉴 안내, 요약 라벨과 공정 흐름 라벨의 대비를 조정했다.

## 자동 검증 범위

### 단위 및 컴포넌트

- 공정 지도 집계, 검색과 상태 필터, 접힌 목록 검색, 목록 포커스 복귀
- 주석 추가와 화면 재진입, 안전 상태별 조치 차단
- 역할별 담당자, 요청 중 잠금, 같은 요청 재시도, 발행 결과 재확인
- API 타임아웃, 취소, 잘못된 요약과 이력 데이터
- 원본 참고값, 시점 공백, 예측 시각 경과, 고정 구간 보정
- 스트림 재연결과 신선도, 링 버퍼와 30분 보관, 늦은 이력 병합
- 차트 범례 선택 유지와 정리, 화면 렌더링 실패 후 다른 화면으로 이동
- 서버 안전 체크리스트, 미지원 이력, 요청 ID 중복 및 충돌 처리

### Chromium E2E

- 정상 역할 전환, 이상 발견, 진단, 주석, 작업 지시 발행
- 센서 이력 장애와 재시도
- 두 화면의 15개 너비: 1920, 1440, 1366, 1280, 1180, 1024, 1000, 821, 820, 701, 700, 521, 520, 390, 320px
- 진단 화면의 12개 너비/높이 조합에서 참고값 카드의 세로 포함 관계, 영역 간 겹침, 카드 하단까지 스크롤 도달 여부
- 주석 입력 전후, 이력 로딩과 실패, 참고값 글자 크기 확대에서 세로 배치 유지
- 모바일 헤더 이름과 키보드 이동, 320px 이력 오류와 다이얼로그
- 요약 API의 최초 HTTP 오류와 잘못된 성공 응답에서 복구
- 미지원 설비 ID에서 허위 데이터가 표시되지 않음
- 전체 근거 이동과 포커스, 긴 주석과 화면 이동 후 유지
- 서버는 발행했지만 응답은 유실된 상황에서 같은 작업 지시 재확인
- 하트비트만 수신할 때 발행 차단과 실시간 KPI 숨김
- 백그라운드 요약 갱신 실패 시 마지막 화면 유지와 재시도
- 1280×540 및 320×568에서 모달 내 모든 조작에 도달
- 실시간 도착 중 차트 고정 구간, 확대와 따라가기
- 공정 개요, 진단, 모달의 데스크톱 및 모바일 axe-core WCAG A/AA 규칙 검사

자동 접근성 검사 통과는 전체 WCAG 준수, Canvas 그래프의 모든 정보를 화면 낭독기로 탐색할 수 있음, 현장 사용성 검증을 뜻하지 않는다.

| 공유 UI/계약 패키지 | Node 테스트 실행 종료 성공, 패키지 내부 테스트는 0개. 소비자 테스트와 타입 검사로 일부 검증 |
| 배포 빌드 | 웹, 서버, 공유 패키지 통과 |
| Storybook | 정적 빌드 통과. 개발 문서용 500KB 초과 청크 경고는 남음 |
| Chromium E2E | 20개 시나리오 모두 통과, 재시도 없이 약 1분에 완료 |

단위 및 컴포넌트 테스트는 각 워크스페이스에서 `--maxWorkers=1`로 순차 실행했다. 중간 E2E 실행에서 근거 목록의 테스트 선택자와 개요 안내 문구 대비를 수정했다. 모바일 접근성 검사도 추가해 공정 단계 가로 스크롤의 키보드 진입 누락을 수정했다. 참고값 카드 잘림의 후속 수정까지 반영한 최종 E2E는 `npm run test:e2e -- -- --workers=1`로 전체를 다시 실행해 20개 모두 통과했다.

기존 이력 장애 테스트는 처음 두 요청만 실패시키는 방식이어서 Strict Mode의 초기 요청 취소와 재실행에 따라 장애가 너무 일찍 해제될 수 있었다. 재시도 버튼을 검증하기 전까지 장애를 유지하는 방식으로 바꿨다. 제품의 오류 처리를 느슨하게 하거나 검사 항목을 제거하지 않았다.

시스템 부하가 매우 높아 타이머까지 지연된 실행은 완료 결과로 인정하지 않고 중지했다. 부하가 내려간 뒤 다른 작업을 건드리지 않고 이번 프로젝트만 낮은 병렬도로 다시 검증했다. 테스트 페이지를 닫는 과정의 Vite 개발 프록시 `EPIPE`/`ECONNRESET` 로그와 색상 환경변수 경고는 남지만, 최종 E2E는 성공 종료했다. 이를 공개 배포의 네트워크 오류가 없다는 증거로 확대하지 않는다.

## 시각 검수 근거와 한계

이번 검토에서 로컬 앱 브라우저로 공정 개요, 진단과 현장 검증 모달의 실제 화면을 캡처하고 확인했다. 유효한 기본 뷰포트는 1280×720이다. 뷰포트 재설정 전 잘못 잘린 캡처는 근거에서 제외했다.

로컬 캡처는 `artifacts/ui-audit/full-review/`에 보관하며 저장소에는 포함하지 않는다.

- `overview-before.png`: 작은 안내 글자, 좁은 설비 코드, 경과한 예상 시각 표시를 확인한 수정 전 화면
- `diagnostics-before-native.png`: 낮은 높이에서의 이벤트 잘림과 차트 위 작은 참고값을 확인한 수정 전 화면
- `dialog-before.png`: 기존 안전 확인 문구와 발행 입력 화면
- `overview-progress.png`: 공개 데모 안내와 개요 구성 변경을 확인한 중간 화면. 최종 색상 변경 이후의 캡처는 아님

이후 앱 브라우저의 URL 정책이 로컬 화면 이동을 차단했다. 다른 브라우저나 우회 경로로 접근하지 않았으며, 최종 진단 및 모달 스크린샷과 전체 화면의 마지막 육안 재검수는 완료하지 못했다. 자동 회귀 테스트와 수동 시각 검수는 구분해 기록한다.

Safari와 Firefox, 실제 브라우저 200% 확대, 실제 화면 낭독기, 현장 터치 패널과 제조 네트워크는 검증 범위 밖이다. 이번 검토의 통과 항목이 모든 장비와 데이터 조건에서 문제가 없다는 보장은 아니다.

## 후속 수정 — 참고값 카드 하단 잘림

사용자가 8월 31일 05:27에 제공한 화면에서 이벤트 영역이 참고값 카드의 우측 장력과 온도 설정값을 덮는 문제가 추가로 확인됐다. 앞선 30개 레이아웃 검사는 가로 넘침을 확인했을 뿐, 부모 영역의 세로 경계를 벗어난 내용이 다음 영역에 가려지는 경우는 검사하지 않았다.

새 세로 회귀 검사는 수정 전 1920×900에서 `.current-values`의 하단이 `.signal-workbench` 아래로 **31px** 넘친다는 결과로 실패했다. 원인은 590px부터 시작하는 차트 영역의 고정 최소 높이와, 도구 모음/표시 구간/420px 차트/참고값 카드의 실제 높이 합계가 맞지 않는 것이었다.

수정에서는 화면 너비별로 전체 높이를 추정하던 590/740/840px 값을 제거했다. 도구 모음, 표시 구간, 차트, 참고값에 각각 Grid 행을 배정하고 부모는 내용 최소 높이를 반영한다. 차트 Canvas는 배정된 행 안에서 크기를 계산하며, 이벤트 영역도 주석 폼과 긴 내용에 맞춰 늘어난다. 부족한 화면 높이는 세로 스크롤로 처리한다.

추가 검사는 1920×900, 1920×720, 1440×900, 1440×540, 1280×720, 1280×540, 1180×720, 1024×768, 701×600, 700×600, 390×844, 320×568에서 수행한다. 주석 입력과 추가, 이력 로딩과 오류, 참고값 글자를 22px로 키운 조건도 포함한다. 글자 크기 변경은 레이아웃 스트레스 검사이며 실제 브라우저 확대 검증은 아니다. 최종 수동 시각 검수의 보류 상태는 그대로 유지한다.

## 데모의 운영 한계

- 실제 설비 연결, 설비 제어, 담당자 통지, 인증과 서버 권한은 구현 범위 밖이다.
- 작업 지시 중복 방지는 해당 인스턴스의 최근 100건에 한정된다. 재시작과 다중 인스턴스에는 영속 저장소가 필요하다.
- 이 검토 시점에는 주석, 미확인 요청과 발행 결과가 탭 메모리에 있었다. 후속 운영 기능 구현에서 미확인 요청과 발행 결과는 IndexedDB로 옮겼다. 현재는 주석과 저장 전 폼 입력이 새로고침 시 초기화된다.
- COATER-02의 최근 30분 이력만 지원한다. 근거가 보관 범위를 벗어나면 오래된 분석으로 새 검증을 발행하지 않는다.
- 8월 30일의 성능 비교는 별도 합성 벤치마크이며 이번 UI 변경의 성능을 다시 측정한 결과가 아니다.

이 검토 당시의 상태: 수정 구현과 자동 검증 완료. 최종 수동 시각 검수는 브라우저 접근 정책으로 보류. 후속 변경의 현재 결과는 문서 상단의 최신 검토 기록을 따른다.
