# NEXUS Forge 제품 명세

## 제품 판단

제품의 중심을 일반적인 공장 현황판이 아니라 “다중 센서 이상 진단과 현장 검증”으로 잡았습니다. 공정 상태를 보여주는 것만으로는 제조 운영자의 의사결정 시간이 줄지 않습니다. 이상 시점, 함께 움직인 신호, 가능한 원인, 안전한 다음 행동을 한 화면에서 연결해야 실무 가치가 생깁니다.

배터리 셀 코팅 공정을 선택한 이유는 장력, 오븐 온도, 라인 속도, 비전 검사 결함률처럼 서로 다른 신호가 품질 결과에 연쇄적으로 영향을 주는 상황을 명확히 보여줄 수 있기 때문입니다.

## 사용자

### 라인 엔지니어

- 설비 앞 또는 제어실에서 현재 이상 여부를 빠르게 판단합니다.
- 정지 여부를 결정하기 전 서로 다른 센서 신호를 같은 시간축으로 확인합니다.
- 안전 조건을 확인한 뒤 현장 점검을 요청합니다.

### 교대 관리자

- 라인 전체에서 생산과 품질 위험이 가장 큰 위치를 찾습니다.
- 원인 추정의 근거와 조치 진행 상태를 확인합니다.

## 핵심 시나리오

1. 코팅 2호 라인의 `COATER-02`에서 웹 장력 편차가 증가합니다.
2. 비전 검사 결함률이 같은 이벤트 구간에서 함께 상승합니다.
3. 사용자는 공정 개요에서 이상 설비를 선택합니다.
4. 진단 화면은 좌우 장력, 오븐 Z3 온도, 라인 속도, 결함률을 동기화해 표시합니다.
5. 원인 사슬은 댄서 롤 위치 편차에서 웹 장력 상승, 엣지 웨이브 결함으로 이어지는 가설을 제시합니다.
6. 라인 엔지니어는 기본 보전 담당자와 안전 조건을 확인하고 작업 지시를 발행합니다. 예상 확인 시간은 약 90초입니다.
7. 교대 관리자는 작업 담당자를 직접 선택해 같은 검증 작업을 위임할 수 있습니다.
8. 정비 관리에서 발행한 작업을 시작하고 점검 결과와 인계 내용을 기록합니다.
9. 이상 관리에서 연결 작업의 완료와 잔여 위험을 확인한 뒤 종결 사유를 남깁니다. 점검 완료는 이상 종결과 별도 상태입니다.
10. 알림에서 각 단계의 관련 기록으로 이동하고 생산 분석에서 사용자 처리 실적을 확인합니다.

### 두 번째 설비로 같은 흐름 확인

`DRYER-02`의 합성 건조 온도 편차도 공정 개요나 설비 목록에서 선택할 수 있습니다. 같은 진단 페이지가 장력 패널 없이 건조로 온도, 라인 속도와 후단 검사 결함률을 표시합니다. 설정값은 165°C, 시나리오상 점검 시간은 120초이며 고온부 접근 없이 외부 계기만 확인하는 안전 조건으로 작업을 발행합니다. 이후 점검과 종결은 같은 업무 명령과 화면을 사용합니다.

두 설비의 데이터, 근거와 발행 결과가 섞이지 않도록 이력과 스트림의 설비 ID를 검사합니다. 다른 설비에 결과 미확인 요청이 있으면 먼저 원래 요청을 복구해야 합니다. 구성 차이와 재사용 한계는 [설비 재사용 사례](./EQUIPMENT_REUSE.md)에 있습니다. 두 시나리오는 독립된 합성 입력이며 실제 라인의 물리 모델이 아닙니다.

## 화면 구성

### 공정 개요 `/overview`

- 믹싱, 코팅, 롤 프레싱, 슬리팅 공정 흐름
- 설비 원본에서 계산한 상태 집계와 이상 설비 강조
- 실시간 웹 장력과 수신 지연, 예상 영향 시간. 수신 중단 시 임의 값을 표시하지 않으며 예상 시각이 지나면 `경과`로 안내
- 활성 인시던트, 주요 원인, 권장 행동

### 신호 진단 `/diagnostics/:equipmentId`

- COATER-02와 DRYER-02 선택, 설비별 이력, 기준값과 안전 조건. 나머지 설비는 상태 조회만 제공
- 설비 ID 검색, 상태 필터, 목록 접기
- 컴팩트한 공정 단계 스트립
- 30분 다중 시계열과 동기화 커서
- 공개 데모 기본 18,000개, 검증 상한 100,000개 이력을 수신. 전체 30분 범위를 최대 20,000개로 보존한 뒤 최대 1,800개 공통 시점으로 요약. 구간별 양 끝과 센서별 최솟값/최댓값, 보존/표시 개수와 해석 한계를 안내
- 작은 국소 피크, 반복 횟수와 지속 시간은 요약 그래프만으로 확정하지 않음. 확대 시 원본 재샘플링은 미지원
- 이상 이벤트 구간과 이벤트 타임라인
- 원인 분석 신뢰도, 원인 사슬, 근거, 권장 조치
- 이벤트 유형 필터와 작업자 주석
- 역할별 안전 사전 확인과 현장 검증 작업 지시 다이얼로그
- 라인 엔지니어의 기본 담당자 확인, 교대 관리자의 담당자 선택
- 작업 지시 상태와 완료 기한 확인, 화면 이동 후 발행 결과 재확인
- 주석은 최대 240자, 최근 50건을 현재 탭 메모리에 보관. 새로고침 시 초기화
- 최초 로딩 실패와 갱신 지연 안내, REST 타임아웃과 재시도
- 작은 화면에서 근거, 현장 검증, 이벤트 영역으로 바로 이동

### 생산 분석 `/production`

- 두 코팅 라인의 최근 24시간/7일과 직전 동기간 비교. 현재 진행 중인 시간대는 제외
- 계획 길이, 검사 길이, 불량 판정 길이에서 계산한 양품 길이와 달성률, 가중 불량률, 라인별 정지 시간의 합계
- 시간별 또는 24시간 구간별 그래프, 같은 수치를 제공하는 표, 필터된 시간별 실적 CSV
- 14일의 결정론적 합성 실적이며 실제 센서 순간값, MES 실적, OEE와 구분
- 선택 라인 자료 부재를 생산량 0으로 간주하지 않음. 부분 누락 시 받은 실적의 범위를 안내하고 이전 기간 증감 비교 보류
- 사용자가 점검을 완료하거나 이상을 종결한 건수는 별도 영역에 표시. 예시 이력과 합성 생산 실적에 혼합하지 않음

### 이상 관리 `/incidents`

- 검색과 상태/심각도 필터, `?incident=ID` 직접 링크
- 목록 선택과 직접 링크에서 상세로 포커스 이동, 목록 복귀 제공. 상태 변경 후 필터에서 빠져도 선택 상세와 다음 작업 유지
- 미확인 → 확인됨 → 조치 중 → 종결 상태와 담당자, 처리 이력
- 발행 결과 미확인 중에는 담당자 변경을 보류. 발행 후 담당자 변경은 진행 중 작업에도 함께 반영
- 연결된 점검을 모두 완료한 뒤 10~500자 종결 사유와 확인 체크를 입력해야 종결 가능
- 저장 전 담당자와 종결 사유는 현재 탭의 화면 이동 중 유지. 같은 담당자 필드의 다른 탭 변경을 자동으로 덮어쓰지 않음

### 정비 관리 `/maintenance`

- 작업 지시 검색, 대기/진행 중/완료와 기한 경과 필터, `?work=ID` 직접 링크
- 발행 시 안전 확인, 담당자, 요청자, 발행 시각과 완료 기한, 변경 이력 조회
- 대기 → 진행 중 → 완료. 점검 시작 전 완료 불가, 10~500자 결과와 인계 확인 필요
- 상태 변경 후에도 선택 작업 유지. 입력 글자 수 안내, 화면 왕복 시 미저장 결과와 인계 확인 복원
- 연결된 이상으로 이동해 별도 종결. 실제 설비 제어나 담당자 전송 없음

### 알림 `/notifications`

- 이상 발생/종결, 작업 발행/시작/완료, 점검 기한 경과 알림
- 유형과 읽음 필터, 개별/전체 읽음, 관련 이상 또는 작업으로 이동
- 빈 필터 초기화, 관련 기록의 보조 설명, 마지막 읽지 않은 항목 처리 후 키보드 포커스 복구
- 최근 200건 보관. 기한 확인은 앱을 열어 둔 동안 30초 간격이며 OS 푸시나 이메일이 아님

### 설정 `/settings`

- 실시간 차트 기본 범위 5/15/30분, KST/UTC, 세 유형의 새 알림 생성 설정
- 브라우저 저장소 상태와 보관 한도, 열람용 JSON 내보내기
- 확인 문구를 입력한 데모 데이터 초기화. 미확인 발행 요청이 있으면 초기화 보류
- 작업, 이상 처리, 알림, 설정은 새로고침 후 복원하고 같은 출처의 브라우저 탭 사이에서 변경을 공유
- 저장 실패를 성공으로 표시하지 않으며, 손상된 저장 기록은 자동으로 덮어쓰지 않음
- 편집 중인 설정은 화면 이동 후에도 유지. 다른 탭의 독립 필드는 반영하고 같은 필드 충돌은 안내와 명시적 되돌리기 제공
- 미저장 입력은 새로고침 시 사라지며 이탈 경고를 요청. 내보내기에는 저장된 문서만 포함
- 다른 탭에서 기록을 완료하거나 초기화해도 현재 탭의 입력을 자동 삭제하지 않음. 공통 `미저장 입력` 영역에서 내용 확인, 해당 기록 이동과 개별 삭제 가능

공통 업무 화면은 읽지 못한 건수를 0으로 표시하지 않습니다. 모바일 버튼과 입력 영역, 고정 헤더를 고려한 포커스 이동, 긴 기록의 줄바꿈을 제공하며 검증 범위와 한계는 [추가 화면 UI/UX 재검토](./OPERATIONS_UI_UX_REVIEW_2026-08-31.md)에 기록합니다.

## 성공 지표

아래 항목은 제품의 목표와 수용 기준입니다. 100,000개 이력과 60분 로컬 부하는 별도로 측정했지만 실제 작업자의 판단 시간, 8시간 현장 부하와 실제 브라우저 200% 확대는 아직 실측 검증하지 않았습니다. 수행한 자동 검사와 남은 범위는 별도의 검토 기록을 따릅니다.

- 이상 설비 발견에서 진단 진입까지 2회 이하의 행동
- 진단 화면 진입 후 10초 안에 이상 시점과 영향 신호 파악
- 원인 근거를 확인한 뒤 같은 화면에서 현장 작업 발행
- 최대 20,000개 시점의 60분 스트림에서 상한, 오류, Long Task와 강제 GC 후 힙 변화를 기록. 누수 부재는 8시간 교대 규모의 후속 수용 기준으로 유지
- 연결 장애 시 자동 재연결 상태를 사용자가 인지할 수 있음
- 하트비트가 살아 있어도 센서 값이 멈추면 정상 상태로 표시하지 않음
- 센서 이력을 검증하지 못한 동안 신뢰도와 작업 발행을 제공하지 않음
- 센서 수신 지연, 근거 시점 부재, 가동 중 점검 불가 상태에서도 작업 발행을 보류
- 응답 유실 후 같은 요청으로 재시도하고, 완료 결과를 확인하기 전 중복 발행을 방지
- 새로고침 이후에도 미확인 발행 요청과 작업 진행을 복원하고, 여러 탭의 독립 변경이 서로 유실되지 않음
- 점검 완료와 이상 종결의 선행 조건, 상태 변경 이력과 알림이 일치함
- 200% 확대와 좁은 운영 패널에서도 핵심 정보가 잘리지 않고 세로로 재배치됨

## 의도적으로 제외한 범위

- 실제 PLC, SCADA, MES 커넥터와 인증
- 실제 온톨로지 저장소와 추론 엔진
- 작업 지시 승인, 감사 로그, 권한 정책의 서버 구현
- 3D 디지털 트윈
- COATER-02와 DRYER-02 외 설비의 상세 진단, 임의 태그 스키마와 30분보다 오래된 센서 이력 조회
- 주석의 서버 저장과 작업 지시의 분산 영속성, 분산 환경의 exactly-once 발행
- 생산 계획 편집, 실제 OEE, 예방 정비 일정과 부품 재고, 알림 외부 발송
- 기기 간 작업 동기화, 서버 백업, JSON 기록 가져오기와 종결 작업 재개방

이 항목은 제품 방향을 흐리지 않으면서 다음 단계에서 확장할 수 있도록 계약과 UI 경계를 분리했습니다.

## 2026년 9월 5일 사용성 및 복구 보강

- 기본 차트 범위가 5분 또는 15분이면 처음 진입한 실시간 추종 상태에서도 보유 이력까지 축소할 수 있습니다.
- 신호 분석에서 마지막으로 선택한 설비는 정비 관리, 설정과 개요를 거쳐 돌아와도 유지합니다.
- 권장 조치와 현재 작업 상태를 원인 후보보다 먼저 제공합니다. 핵심 근거와 설비 글씨를 확대하고, 모바일 공정 단계와 기술 설명은 접어서 제공합니다.
- `신호 표시와 시점별 값 확인`을 펼치면 체크박스, 슬라이더와 이전/다음/최신 시점 버튼으로 신호와 값을 조회할 수 있습니다. 표는 숨긴 신호도 포함하며, 고밀도 데이터는 보존 버퍼의 요약값임을 안내합니다.
