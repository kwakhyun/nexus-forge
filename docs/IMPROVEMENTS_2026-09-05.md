# 검토 후 개선 기록 — 2026년 9월 5일

[수정 전 검토](./PROJECT_REVIEW_2026-09-05.md)의 오류, 디자인, 접근성, 최적화와 구조 개선 항목을 로컬 소스에 반영했습니다. 공개 데모 배포 여부와 이번 로컬 검증은 별개입니다.

## 반영 내용

| 검토 항목 | 구현과 확인 지점 |
| --- | --- |
| 이력 만료 후 발행 요청 복구 차단 | 신규 POST와 `GET /api/verifications/by-request/:requestId` 조회를 분리했습니다. 이력 만료, 새로고침과 설비 이동 후에도 기존 결과를 조회하며 자동 재발행하지 않습니다. 서버에 결과가 없으면 미확정으로 안내하고 명시적으로 추적 종료한 이력을 남깁니다. |
| 기본 5분/15분 범위에서 축소 불가 | 축소 버튼은 추종 상태 대신 실제 표시 기간과 보유 이력을 비교합니다. 5분, 15분과 30분의 초기 버튼 상태를 검사합니다. |
| 정비 관리 후 진단 설비가 바뀜 | 마지막 진단 설비와 현재 스트림 구독 설비를 분리했습니다. DRYER-02에서 업무와 개요를 거친 뒤에도 DRYER-02로 복귀합니다. |
| 작은 글씨와 행동 위계 | 주요 근거, 설비 정보와 안내 글씨를 키웠습니다. 권장 조치를 원인 후보보다 먼저 배치하고 기술 설명을 접었습니다. 모바일 공정 단계도 기본으로 접습니다. |
| Canvas 조작의 키보드 대안 부족 | 신호 체크박스, 시점 슬라이더, 이전/다음/최신 버튼과 한 시점의 값 표를 제공합니다. 보존 이력 만료와 고밀도 요약의 한계를 안내합니다. |
| 불필요한 수신과 전체 옵션 갱신 | 비진단 업무 화면과 숨겨진 탭의 구독 및 타이머를 중단합니다. 진단 복귀 시 이력을 재조회합니다. 중복 배치는 상태를 발행하지 않으며 일반 차트 갱신은 시리즈 데이터와 표시 범위만 전달합니다. |
| 파일 및 UI 책임 분리 | 업무 명령과 문서 검증을 `domain/workspace/`로, 상세 UI를 `components/operations/`로, 스타일을 `styles/`로 분리했습니다. 생산 집계를 도메인으로 이동하고 공통 Button 테마와 StatusBadge pill을 업무 화면에 적용했습니다. Storybook에도 밝은 테마를 추가했습니다. |
| 검증 신뢰도 | 캐시를 우회한 단위 검사를 실행하고 브라우저 검사는 배포용 빌드로 전환했습니다. 대용량 생성 검사의 시간 제한만 명시하고 일반 UI 검사의 제한 시간을 일괄 늘리지 않았습니다. |

업무 저장은 기존 IndexedDB 트랜잭션과 v1 문서 형식을 유지합니다. 미확정 요청을 종료하거나 확정할 때 최신 요청 ID를 대조해 오래된 탭의 결과가 다른 요청을 지우지 않도록 했습니다. 추적 종료는 발행 취소나 미발행 확인이 아닙니다.

브라우저 검사는 로컬 production preview와 Chromium을 사용했습니다. Firefox, WebKit과 공개 배포 검증은 이번 범위에 포함하지 않았습니다.

### 검증 과정에서 보완한 점

개발 서버에서 첫 모듈을 불러오는 과정의 지연과 테스트 시간 초과를 관찰해, E2E를 웹과 서버의 배포용 빌드로 전환했습니다. 테스트가 서버를 독립적으로 시작하고 종료하며 기존 개발 서버를 재사용하지 않습니다.

배포용 첫 전체 실행에서는 58개가 통과하고 3개가 실패했습니다. 모바일 접힌 설비 목록의 높이 부족은 CSS에서 수정했고, 기본으로 접도록 변경한 설명과 공정 단계는 펼친 다음 검사하도록 갱신했습니다. 이어 설정 저장 완료 전에 페이지를 떠나던 검사에 성공 상태 대기를 추가하고, 키보드 초점 검사는 Enter로 펼치는 실제 키보드 동선으로 정리했습니다. 일반 UI 검사 제한 시간을 늘려 실패를 숨기지 않았습니다.

## 범위와 한계

- 신규 자동 검사에는 응답 유실과 이력 만료 조합, 미확정 추적 종료, 키보드 신호 조작과 설비 복귀를 포함했습니다. 이력 만료는 응답 fixture의 시각을 바꿔 재현하며 실제 30분 대기는 아닙니다.
- 서버 발행 기록은 여전히 최근 100건의 인스턴스 메모리입니다. 조회 결과가 없다고 미발행을 보장할 수 없습니다. 인증, 영속 멱등성과 다중 기기 동기화는 공개 데모의 기존 미지원 범위입니다.
- 접근성 개선은 native HTML 조작과 Chromium 키보드 검사를 근거로 합니다. 스크린리더 전수 검사나 접근성 표준 전체 준수를 주장하지 않습니다.
- 과거 10만 시점과 60분 벤치마크는 당시 소스의 결과로 보존합니다. 이번 최적화의 속도 개선율로 사용하지 않습니다.
