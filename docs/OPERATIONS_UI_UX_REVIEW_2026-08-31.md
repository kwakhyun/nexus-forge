# 추가 운영 화면 UI/UX 재검토 — 2026년 8월 31일

후속 보강으로 두 번째 설비의 [진단 재사용](./EQUIPMENT_REUSE.md)과 [실제 앱 성능 계측](./PERFORMANCE.md)을 추가했다. 아래는 그 이전의 검토 기록이다.

이 문서는 운영 화면 재검토 당시의 결과다. 이후의 다중 센서 피크 수정, 성능 재측정과 현재 검증 상태는 [제출 준비 기록](./SUBMISSION_REVIEW_2026-08-31.md)을 따른다. 아래 테스트 수와 결과는 당시 기록으로 보존한다.

후속 직접 확인에서는 아래 다섯 운영 화면을 포함한 일곱 화면과 두 설비의 핵심 흐름을 대표 화면 크기에서 확인했다. 목록, 검색, 입력 검증, 완료와 종결, 새로고침 복원, CSV/JSON 파일 및 오류 복구를 확인하고 캡처를 보관했다. [전 화면 직접 검수](./BROWSER_REVIEW_2026-08-31.md)는 당시 기록이며, 이후 모바일 16조건과 일반 키보드 확인 및 공개 반영은 [최종 검증 기록](./FINAL_VERIFICATION_2026-08-31.md)으로 구분한다.

## 범위와 근거

생산 분석, 이상 관리, 정비 관리, 알림, 설정과 기존 신호 진단을 연결한 업무 흐름을 검토했다. 이 문서는 당시 로컬 작업 트리의 후속 검토이며 [최초 다섯 메뉴 구현 기록](./OPERATIONS_MODULES_2026-08-31.md)과 구분한다. 이 검토 단계에서는 커밋, 푸시와 공개 배포를 수행하지 않았고 이후 결과는 상단 최신 기록을 따른다.

이 검토 당시에는 브라우저 접근 정책 때문에 최종 캡처 검수를 보류했다. 다른 브라우저나 접속 경로로 우회하지 않았다. 아래 근거는 당시 소스 검토, 단위 테스트와 Chromium E2E 결과다. 이후의 대표 화면 직접 확인은 상단 후속 기록을 따르며, 실제 화면 낭독기 검증을 완료했다는 뜻은 아니다.

## 재현한 결함과 수정

| 문제 | 수정 전 근거 | 수정 |
| --- | --- | --- |
| 상태 필터 안에서 처리하면 상세가 사라짐 | `미확인` 필터에서 이상 확인 후 `이상 상세` 요소를 찾지 못해 회귀 테스트 실패 | 선택 ID를 URL에 유지하고 목록 필터와 상세 조회를 분리. 상태가 바뀌어 목록에서 빠져도 완료 안내와 다음 작업 유지 |
| 모바일 목록 선택 후 상세와 포커스가 멀리 남음 | 390×667에서 선택한 상세 제목에 키보드 포커스가 없어 검사 실패 | 목록 선택과 직접 링크에서 상세 제목으로 이동, 목록 복귀 버튼 제공. 고정 헤더 높이를 측정해 이동 대상이 가리지 않도록 여백 적용 |
| 미저장 설정이 화면 이동과 외부 저장으로 소실 | 차트 범위를 5분으로 바꾸고 화면 왕복 후 30분으로 돌아가 회귀 테스트 실패 | 미저장 입력을 탭 메모리에 따로 보관. 다른 탭의 변경은 편집하지 않은 필드에만 반영하고 같은 필드 충돌은 사용자에게 확인 요청 |
| 저장소 오류를 계속 로딩 중으로 표시 | IndexedDB 접근 차단 뒤 오류가 아닌 `운영 기록을 준비하고 있습니다`가 남음. 확장 검사에서는 목록 필터의 `0건 / KST`도 실패로 확인 | 조회 실패와 준비 상태를 분리. 업무 지표는 `—`, 세 목록의 결과 수는 `건수 미확인`으로 표시 |

위 네 테스트는 수정 전에 모두 실패했고 수정 후 모두 통과했다. 제품의 검사를 느슨하게 하거나 실패 기대값을 삭제하지 않았다.

최종 다중 탭 경계 검토에서는 다른 탭의 완료로 폼이 읽기 전용으로 바뀌면 현재 탭의 미저장 점검 결과가 삭제되는 문제도 재현했다. `useWorkspaceDraft.test.tsx`에서 읽기 전용 전환 후 입력 유지 검사가 실패한 것을 확인한 뒤, 외부 상태 전환이 초안 삭제를 수행하지 않게 바꿨다. 해당 기록이 완료되거나 없어져도 `미저장 입력` 영역에서 내용을 확인하고 개별 삭제할 수 있다. 이는 저장된 결과를 덮어쓰거나 재개방하는 기능이 아니다.

추가로 다음 경계를 보강했다.

- 정비 결과와 종결 사유의 10~500자 기준을 입력란에서 설명하고 앞뒤 공백을 제외한 글자 수를 표시한다. 긴 영문 참조값과 여러 줄 기록을 줄바꿈한다.
- 미저장 담당자, 점검 결과, 종결 사유와 설정을 화면 이동 중 유지한다. 저장이나 명시적 취소 후 제거하며 새로고침 전에는 이탈 경고를 요청한다. 다른 탭의 완료나 초기화로 자동 삭제하지 않는다. 입력 취소 후에는 해당 폼이나 화면 제목으로 포커스를 복구한다.
- 설정은 변경한 필드만 최신 DB 문서에 적용한다. 같은 필드를 다른 탭에서 바꾼 경우 DB 트랜잭션에서도 비교해 오래된 입력이 덮어쓰지 못하게 한다. 담당자 변경도 편집 시작값을 비교한다.
- 버튼이 처리 후 사라지면 키보드 포커스를 성공 안내로 복구한다. 새 화면 제목, 목록과 상세에 포커스를 제공한다. 읽지 않은 마지막 알림 처리 후에도 탐색을 이어갈 수 있게 한다.
- 알림의 관련 기록 버튼에 알림 제목을 보조 설명으로 연결하고 빈 필터 결과에는 초기화 버튼을 제공한다.
- 모바일의 공통 버튼과 입력란은 44px 이상 조작 영역을 사용한다. 입력 글자는 16px로 두고 기본 글자 확대에 대응한다. 이는 iOS 실기기 검증을 뜻하지 않는다.
- 생산 실적의 누락과 0을 구별한다. 빈 라인은 빈 상태로 표시하고 CSV를 비활성화한다. 일부 기간 자료가 없으면 경고하고 이전 기간 증감 비교를 보류한다. 동일 라인/시간대 중복도 응답 검증에서 거부한다.
- 합성 서버가 재시작해 같은 이상 ID의 시각을 바꾸더라도 기존 업무 기록의 발생 시각은 유지한다. 기록된 이상이 이미 완료한 작업보다 나중에 발생한 것처럼 뒤바뀌지 않게 한다.

## 데이터 수명과 사용자 기대

| 데이터 | 보관 위치 | 화면 이동 | 새로고침 | 다른 탭 |
| --- | --- | --- | --- | --- |
| 저장한 작업, 이상 처리, 알림, 설정, 미확인 발행 요청 | 해당 출처의 IndexedDB | 유지 | 복원 | 같은 출처와 브라우저 안에서 공유 |
| 저장 전 담당자, 점검 결과, 종결 사유, 설정 입력 | 현재 탭의 `workspaceDraftStore` | 유지 | 사라짐, 이탈 경고 요청 | 공유하지 않음 |
| 이벤트 주석 | 현재 탭의 `operationsStore` | 유지 | 사라짐 | 공유하지 않음 |
| 센서 이력과 차트 조작 상태 | Query, 링 버퍼, 차트 컴포넌트 | 다시 조회하거나 해당 화면 수명에 따름 | 다시 조회 | 저장 기록으로 동기화하지 않음 |

작성 중인 입력은 저장된 작업이나 내보내기 JSON에 포함되지 않는다. `beforeunload` 경고는 브라우저 정책에 따라 표시되며 강제 종료, 사이트 데이터 삭제, OS 저장 공간 정리까지 막지 못한다. 데모 초기화는 저장 문서와 초기화를 실행한 탭의 주석 및 미저장 입력을 지운다. 다른 탭에 남은 입력은 해당 탭에서 확인 후 지우도록 한다.

## 검증 시나리오

검사 코드는 [workspace-review.spec.ts](../apps/web/e2e/workspace-review.spec.ts)에 추가했다.

1. 상태 필터를 적용한 이상의 확인 후 상세, 안내와 담당자 변경 유지
2. 모바일 목록 선택, 상세 포커스와 목록 복귀, 고정 헤더에 가리지 않는지 검사
3. 화면 이동 중 설정 초안 유지, 다른 탭의 독립 필드 변경 병합과 새로고침 복원
4. 저장소 접근 실패가 무한 로딩이나 업무 0건으로 표시되지 않음
5. 같은 설정 필드의 동시 수정 충돌 안내, 명시적 되돌리기
6. 320×568에서 실제 API 작업 발행 → 필터 안에서 시작 → 500자 결과 작성 → 화면 왕복 → 완료 → 500자 종결 사유 → 화면 왕복 → 종결 → 새로고침 복원
7. 읽지 않은 마지막 알림을 키보드로 처리한 후 포커스와 필터 복구
8. 생산 자료 일부 누락과 선택 라인 자료 부재, 복구 가능한 필터와 내보내기 상태
9. 다섯 화면의 긴 기록과 보관 한도 스트레스: 작업 100건, 알림 200건, 선택 기록의 처리 이력 100건, 제목 200자와 기록 500자
10. 다른 탭의 점검 완료 후 현재 탭의 미저장 결과 보존, 보관 내용과 저장된 결과의 구분, 명시적 삭제와 포커스 복구

스트레스 검사는 1440×600, 1280×560, 1024×600, 700×667, 390×667, 320×568의 여섯 화면 크기로 수행한다. 320px에서 주요 글자를 22px로 키운 조건도 추가한다. 문서와 요소의 가로 넘침, 숨겨진 세로 넘침, 내용이 카드의 세로 경계를 벗어나는지, 마지막 작업 영역에 도달할 수 있는지와 axe-core 규칙을 검사한다. 큰 글씨 주입은 실제 브라우저 200% 확대 검증과 다르다. 대량 기록은 격리된 테스트 브라우저에 주입하는 합성 fixture이며 실사용자 데이터가 아니다.

E2E의 기존 정상 화면 가로 경계 55개와 진단 세로 경계 12개 화면 크기 검사도 유지했다. 신규 검사는 긴 기록과 처리 전후 상태를 추가하는 것이며 기존 검사를 대체하지 않는다. 페이지를 닫을 때 발생하는 Vite 개발 프록시의 `EPIPE`/`ECONNRESET` 로그와 색상 환경변수 경고는 남아 있다. 성공 종료를 공개 배포에서 네트워크 오류가 없다는 증거로 확대하지 않는다.

문서는 현재 기능 명세와 과거 구현 기록을 구분했다. README, 제품 명세, 아키텍처, API와 결정 기록의 저장 범위 및 상태 전이를 맞췄고, 이전 검토의 테스트 수와 스크린샷에는 해당 시점의 근거임을 표시했다. 8월 30일 성능 측정값은 다시 측정한 것처럼 바꾸지 않았다.

## 후속 보강과 별도 검증 범위

- 대표 화면과 핵심 업무 흐름의 직접 검수는 [후속 보고서](./BROWSER_REVIEW_2026-08-31.md)에서 완료했다. 당시 남았던 반복 조건과 일반 키보드 조작도 이후 [Playwright 검사](./FINAL_VERIFICATION_2026-08-31.md)로 확인했다.
- Safari와 Firefox, 실제 브라우저 확대 및 화면 낭독기
- 실기기의 터치 입력, 현장 네트워크, 실제 제조 데이터, 다중 사용자 승인과 업무 인터뷰
- 당시 부족했던 전체 앱 성능은 이후 [8월 31일 측정](./PERFORMANCE.md)으로 보강했다. 그보다 나중에 수행한 바로가기와 집계 수정의 재측정 결과는 아니다.

자동 검사에서 발견한 결함을 수정하는 것과 모든 장비의 UI/UX가 무결하다고 보증하는 것은 구분한다.
