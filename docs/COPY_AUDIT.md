# 화면 문구 검토 기록

이 문서의 스크린샷과 아래의 초기 검토 결과는 당시 구현의 기록이다. 운영 화면의 후속 변경은 [운영 화면 재검토](./OPERATIONS_UI_UX_REVIEW_2026-08-31.md), 현재 검사와 공개 반영 상태는 [최종 검증 기록](./FINAL_VERIFICATION_2026-08-31.md)을 따른다. 기존 진단의 이전 검토는 [전체 검토 기록](./UI_UX_REVIEW_2026-08-31.md)에 보관한다.

## 제출 검토에서 보강한 차트 문구

- 보존 센서 시점 수와 차트에 표시하는 시점 수를 구분한다. 1,800개는 고정 개수가 아닌 상한이다.
- `구간별 최솟값과 최댓값을 표시합니다. 작은 반복 피크나 지속 시간은 이 요약만으로 판단할 수 없습니다.`로 보장 범위를 안내한다.
- README에서도 모든 이상값이 보존되거나 차트 단독 비교가 전체 앱 성능인 것처럼 표현하지 않는다. 후속 [전체 흐름 계측](./PERFORMANCE.md)은 별도 실험이며 측정 구간과 한계를 구분한다.

## 운영 화면 후속 문구 보강

- `저장한 기록`, `아직 저장하지 않은 입력`, `현재 탭의 주석`을 구분한다. 업무 입력은 화면 이동 중 유지하지만 새로고침 시 사라지며 저장 완료 기록만 JSON에 포함한다.
- 다른 탭에서 이미 완료한 작업에는 작성 중이던 입력이 결과에 반영되지 않았음을 알린다. `미저장 입력`에서 보관 내용을 확인하고 `이 입력 지우기`로 삭제하도록 구분한다.
- 결과와 종결 사유에 `앞뒤 공백을 제외하고 10자 이상`과 500자 한도를 설명한다.
- 상태 변경으로 선택 기록이 필터에서 빠졌다는 안내와 `목록으로 돌아가기`를 제공한다.
- 저장소를 읽지 못했을 때 `0건`이나 계속 `준비 중`으로 표시하지 않는다.
- 부분 생산 자료와 없는 실적을 측정한 생산량 0으로 해석하지 않도록 안내한다.
- 설정 충돌은 입력을 보존한 상태로 설명하고 `저장된 설정으로 되돌리기`를 제공한다. `전체 읽음 처리`는 필터 결과가 아닌 전체 알림에 적용한다.

## 2026년 8월 31일 추가 변경

- 이후 생산 분석, 이상 관리, 정비 관리, 알림, 설정을 실제 화면과 업무 기능으로 구현하여 사이드바의 `미제공` 표기를 제거했다. 현재 범위는 [운영 기능 확장 기록](./OPERATIONS_MODULES_2026-08-31.md)을 따른다.
- `발행`, `점검 완료`, `이상 종결`을 구분했다. 완료 예시에는 `예시 기록`, 합성 생산 지표에는 `합성 코팅 실적`을 표시한다. 합성 수치와 사용자가 남긴 처리 실적을 섞지 않는다.
- 업무 기록과 설정은 `이 브라우저에 저장`, 주석은 `새로고침 시 초기화`로 보관 범위를 나눴다. 실제 전송이나 기기 간 동기화를 제공하는 것처럼 표현하지 않는다.
- `선택값`을 `이상 발생 시점 참고값`으로 바꾸고 기준 시각을 함께 표시했다. 마우스 커서의 현재 위치나 실시간 센서 값으로 오인하지 않게 했다.
- 일반적인 가동 중 점검 허용 문구와 고정 속도 확인 항목을 제거했다. 현장 작업 표준과 안전 조건을 확인해야 하며, 데이터가 준비되지 않으면 발행을 보류한다.
- 모든 화면에 `공개 데모`를 표시하고 가상 데이터, 역할 체험, 실제 설비 제어와 작업 전송이 없다는 범위를 안내했다.
- 작업 지시 완료 후에는 `발행한 작업 지시 보기`, 응답을 확인하지 못하면 `같은 요청으로 다시 확인`을 제공해 다음 행동을 구분했다.
- `확산까지 0분`이 계속 표시되던 상태를 `예상 확산 시각 경과`로 구분하고 실제 확산 여부는 확인되지 않았다고 안내했다.
- 초기 보강에서는 주석과 발행 결과 모두 새로고침 시 초기화된다고 설명했다. 후속 구현에서 발행 결과와 미확인 요청을 IndexedDB로 옮겼다. 현재는 주석과 미저장 입력이 새로고침 시 초기화된다. 상세 진단은 이후 COATER-02와 DRYER-02로 확장했으며, 나머지 설비와 30분 이전 이력은 제공하지 않는다.

## 초기 검토 범위

공정 개요에서 이상 설비를 찾고, 신호를 분석한 뒤 현장 검증 작업 지시를 발행하는 전체 흐름을 검토했습니다. 화면에 노출되는 제목, 상태, 센서명, 이벤트, 도움말, 버튼, 오류 메시지와 접근성 이름을 포함했습니다.

## 사용자 목표

라인 엔지니어와 교대 관리자가 제조 현장 용어를 별도로 해석하지 않고도 현재 상태와 다음 행동을 빠르게 이해하는 것이 목표입니다.

## 흐름별 결과

### 1. 공정 개요 — 양호

공정명, 라인명, 이상 영향 시간과 권장 조치를 자연스러운 한국어로 정리했습니다. 하드코딩된 “4분 전”을 실제 발생 경과 시간으로 교체했습니다.

![개선 후 공정 개요](./copy-audit/01-overview-after.png)

### 2. 신호 진단 — 양호

센서명, 차트 제어, 선택 시점 값, 이벤트명, 원인 후보와 근거 단위를 통일했습니다. 긴 문구가 세 영역 레이아웃에서 잘리거나 겹치지 않는 것을 확인했습니다.

![개선 후 신호 진단](./copy-audit/02-diagnostics-after.png)

### 3. 안전 조건 확인 — 양호

모달의 목적을 “원인 검증”에서 “현장 검증”으로 구체화하고, 각 체크 항목이 무엇을 확인했는지 완전한 문장으로 작성했습니다. 라인 엔지니어에게는 기본 보전 담당자를 읽기 전용으로 표시해 안전 확인에 집중하도록 했습니다.

![개선 후 안전 조건 확인](./copy-audit/03-verification-after.png)

### 4. 작업 지시 완료 — 양호

“요청이 발행되었습니다”를 “작업 지시를 발행했습니다”로 바꿔 주체와 결과를 분명하게 표현했습니다.

![개선 후 작업 지시 완료](./copy-audit/04-success-after.png)

### 5. 교대 관리자 행동 — 양호

역할별 버튼을 라인 엔지니어의 “현장 검증 시작”과 교대 관리자의 “현장 검증 요청”으로 구분했습니다. 교대 관리자 모달에서만 작업 담당자를 선택할 수 있어 버튼 문구와 실제 권한이 일치합니다.

![개선 후 관리자 화면](./copy-audit/05-manager-after.png)

### 6. 이력 장애와 복구 — 양호

이력 조회가 실패하면 장애 범위와 재시도 행동을 함께 안내합니다. 원인 후보는 `이력 미확인, 참고용`으로 낮춰 표시하고, 신뢰도는 `분석 보류`로 대체하며 현장 검증 버튼을 비활성화합니다. 이력을 다시 불러오는 데 성공하면 경고가 사라지고 신뢰도와 작업 버튼이 함께 복구되는 것을 확인했습니다.

## 접근성 확인

- 검색창과 필터의 접근성 이름을 화면 용어와 같은 “설비”로 통일했습니다.
- 차트 설명에 비교 대상과 같은 시간축이라는 의미를 포함했습니다.
- 과거 선택 시점의 값을 보조 기술에서도 “현재값”으로 오해하지 않도록 이름을 수정했습니다.
- 역할별 버튼의 접근성 이름과 보이는 문구가 일치하는 것을 DOM에서 확인했습니다.
- 이력 장애 경고는 즉시 알림으로 한 번만 전달하고, 우측 분석 보류 설명은 중복 경고 대신 상태 정보로 제공합니다.

스크린샷과 DOM으로 문구, 읽기 순서, 잘림 여부를 확인했습니다. 실제 스크린 리더의 한국어 발음 품질과 현장 소음 환경에서의 인지성은 별도의 사용성 시험이 필요합니다.
