# 릴리스 준비와 검증 기록 — 2026년 8월 31일

## 상태

다중 센서 피크 누락을 수정하고 릴리스 버전과 기술 판단 사례를 정리했다. 후속 요청으로 두 번째 설비 DRYER-02와 실제 앱 전체 흐름의 성능 계측을 추가했다. 이 문서는 **배포 전 로컬 검증**과 **배포 후 공개 사이트 직접 확인**을 구분해 기록한다. 구현 버전 `20ad702`의 커밋과 푸시, [GitHub Actions 검증 및 배포](https://github.com/kwakhyun/nexus-forge/actions/runs/33348358328)는 완료했다.

**대표 화면과 핵심 흐름의 직접 검수는 완료했다.** 11:15~12:00 KST에 같은 내장 브라우저로 일곱 화면, 두 진단 설비, 하단 스크롤, 안전 확인과 발행, 점검 완료 및 별도 종결, 새로고침 복원과 오류 복구를 확인했다. 발견한 네 건을 로컬에서 수정했고 캡처 44장을 저장했다. [직접 검수 보고서](./BROWSER_REVIEW_2026-08-31.md)에 화면별 근거를 기록했다.

약 12:03 KST에 중단했던 추가 모바일 조건과 일반 키보드 조작은 이후 저장소 Playwright에서 확인했다. 현재 메뉴가 화면 밖에 남는 다섯 번째 결함을 수정했고, 최종 GitHub CI에서 웹 단위 101개, 서버 14개와 E2E 58개가 통과했다. `5474706`의 자동 배포와 공개 SHA 대조도 완료했다. 당시 릴리스 범위에 남은 미완료 항목은 없으며, [최종 검증 기록](./FINAL_VERIFICATION_2026-08-31.md)에 근거와 운영 한계를 구분했다. 아래의 11시 직접 검수와 98개 단위 검사 등은 각 실행 시점의 기록으로 보존한다.

### 이전 로컬 검수 중단 기록

앞선 로컬 검수에서는 사용자 허용 이후 공정 개요와 DRYER-02 진단의 내용과 초기 화면을 확인했다. 이후 크기 조정/캡처 시 URL 정책이 접근을 차단했고 정리 요청에서도 내장 브라우저의 `This page crashed` 오류 페이지가 차단 대상으로 반환됐다. 앱 또는 도구 중 어느 쪽이 원인인지는 확정하지 못했고, 당시에는 다른 브라우저나 주소로 캡처를 우회하지 않았다. 이 중단 기록과 이후 11시 직접 확인, 12:03의 새 접근 제한을 시간순으로 구분한다.

저장소의 자동 회귀 테스트와 별도 로컬 성능 런타임은 화면 직접 검수와 구분해서 수행한다. 자동 테스트의 실패 캡처를 최신 대표 이미지로 사용하지 않는다. 기존 대표 이미지도 과거 구현 기록으로 유지한다.

## 수정한 내용

### 차트의 데이터 보존

- 동일 구간의 장력 90N과 온도 180°C가 경쟁할 때 장력 피크가 사라지는 반례를 단위 및 차트 전달값 테스트로 재현했다.
- 가중 변화량으로 하나만 고르는 방식에서 공통 구간의 경계와 센서별 최솟값/최댓값 시점을 합치는 방식으로 바꿨다.
- 여섯 차트 시리즈의 추가 샘플링을 끄고, 원본/표시 시점 개수와 요약 해석 한계를 화면에 표시했다.
- 최대 1,800개는 상한이다. 모든 국소 피크, 반복 횟수와 지속 시간은 보장하지 않으며 확대 시 원본 재샘플링은 미지원이다.

### 성능 근거

- 측정 스크립트가 앱의 실제 샘플러를 빌드해 호출하도록 바꿨다. 예열 3회와 반복 60회, 실제 출력 개수, 개별 표본, 소스 SHA-256을 기록한다.
- 동기 차트 렌더 외에 샘플링과 옵션 준비 시간을 별도로 측정한다. 합성 차트 준비 + 렌더 중앙값은 같은 실행에서 35.4ms → 9.3ms다.
- 단위 테스트와 겹친 초기 측정은 최종 스냅샷에서 제외하고, 독립 실행한 [8월 31일 결과](./benchmarks/performance-2026-08-31.json)를 기록했다. 비교 조건과 제외 범위는 [성능 문서](./PERFORMANCE.md)에 있다.
- 8월 30일의 원본 수치는 그대로 보존하고 과거 알고리즘 측정으로 구분했다.
- [전체 앱 측정기](../scripts/benchmark-application.mjs)는 실제 웹 워크스페이스의 Vite와 공통 서버 런타임을 사용한다. 설비 클릭부터 진단 코드 로딩과 이력 반영, 실시간 배치, 확대/이동, API 발행과 IndexedDB 저장 이후의 프레임을 각각 기록한다.
- 계측은 별도 opt-in 빌드에만 있다. 일반 배포 빌드에서는 전역 계측 객체와 관찰자를 만들지 않는다. 해당 동작과 기록 경계의 단위 검사 5개를 추가했다.
- 설비별 3회 × 30초와 별도 180초 수신을 완주한 [전체 흐름 원본](./benchmarks/application-flow-2026-08-31.json)을 보관했다. 설비 클릭 → 첫 이력 반영 중앙값은 COATER-02 489.4ms, DRYER-02 463.9ms다. 로컬 프로덕션 빌드의 값이며 공개 사이트의 성능이나 전후 개선율이 아니다.
- 연속 관찰 구간의 Long Task는 없었으나 초기 진입에 7개, 최대 63ms가 있었다. 3분간 힙 관측값이 모두 같아 메모리 추이나 누수 판단의 근거로 사용하지 않는다.
- 짧은 계측기 점검과 클릭 시각 계측 추가 전에 중단한 실행은 본 결과에 섞지 않는다. 표본 수와 구간 정의, 해석 한계는 성능 문서에서 별도 공개한다.

### 두 번째 설비 재사용

- DRYER-02의 실제 합성 이력, 구독 ID, 3개 패널과 165°C 설정값, 외부 계기 점검 안전 계약을 공통 페이지에 연결했다.
- 늦은 과거 설비 응답과 프레임, 발행 결과가 현재 설비에 섞이지 않도록 검사했다. 다른 설비의 미확인 발행 요청은 새 요청으로 덮어쓰지 못한다.
- 건조기 작업 발행부터 점검 완료, 새로고침 복원과 미확인 요청 재시도까지 회귀 검사했다. 같은 신호 어휘 안의 두 합성 구성이며 실제 두 번째 현장 적용은 아니다. [변경 지점과 제한](./EQUIPMENT_REUSE.md)을 공개했다.

### 이번에 발견한 화면과 검사 문제

- 초기 직접 화면에서 설비 목록 하단의 고정 버튼이 항목을 가리고 차트 도구 모음의 시점 개수가 잘리는 문제를 확인했다. 버튼을 일반 흐름에 두고 도구 모음과 통계를 줄바꿈했다. 변경 후 자동 경계 검사는 통과했다. 후속 직접 검수에서 설비 목록 하단, 참고값과 이벤트, 대표 모바일의 도구 모음도 캡처로 확인했다. 모든 화면 크기의 조합을 확인한 것은 아니다.
- React의 `<title>`에 설비 ID와 문자열을 여러 자식으로 전달해 진단 제목이 비던 오류를 axe 검사에서 발견했다. 단일 문자열로 수정하고 두 설비의 문서 제목 검사를 추가했다.
- 진단 설비가 하나, 최초 이상이 세 건, 새 알림이 한 건이라는 기존 테스트 가정을 갱신했다. 실패한 기능 검사를 삭제하지 않고 새 개수와 명확한 대상 선택으로 보강했다. 긴 기록의 테스트 데이터도 두 활성 이상을 포함하도록 갱신했다.

앞선 E2E 실행에서는 시점 개수 표시를 원본과 표시 개수로 나눈 변경 때문에 기존 문구 선택자가 실패했다. 이번에는 설비 추가 이후의 선택자와 테스트 데이터 가정, 비어 있는 문서 제목 문제가 실패했다. 수정 후 전체를 재실행했다. 실시간 수신 중 고정 구간 유지, 확대/따라가기, 최종 읽음 처리의 포커스와 긴 기록 검사는 제거하지 않았다.

배포 직전 재실행에서는 설정 복원 검사 한 건이 이력 도착 전에 0초 구간을 읽어 실패했다. 실패 직후 DOM 기록에는 정상적인 5분 범위가 표시됐다. 설정 문구가 나타나는 시점과 이력 로딩 완료 시점을 구분하지 않은 검사 경쟁 조건이었다. 이력 응답을 명시적으로 보류해 로딩 안내와 조작 제한을 검사하고, 응답을 재개한 뒤 원본 참고값과 실제 300초 표시 범위를 기다리도록 보강했다. 지연 조건에서 3회 반복 통과 후 전체 53개를 다시 통과했다. 앱과 성능 측정 소스는 변경하지 않았다.

최종 E2E는 통과했지만 페이지 종료 시 Vite 프록시의 `EPIPE`/`ECONNRESET` 로그와 색상 설정 경고가 남았다. 테스트 통과를 모든 네트워크 로그가 오류 없이 끝났다는 의미로 해석하지 않는다.

```bash
npm test
npm run lint
npm run typecheck
npm run build
npm run storybook:build
npm --workspace @nexus/web run test:sites
npm run benchmark:performance
npm run test:e2e
npm run benchmark:application
```

위 명령은 검사별 실행 기록이며 성능 측정 중에 빌드나 테스트를 병렬로 실행하지 않는다. Chromium의 자동 레이아웃과 axe 검사도 Safari, Firefox, 실제 화면 낭독기, 실기기나 최종 육안 검수를 대신하지 않는다. 의존성 감사 0건은 8월 30일의 이전 기록이며 이번에 재검사한 값이 아니다.
