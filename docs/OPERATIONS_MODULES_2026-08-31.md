# 운영 기능 확장 — 2026년 8월 31일

이 문서는 다섯 메뉴를 처음 구현한 시점의 기록이다. 아래 테스트 수와 실행 결과는 당시 기준이며 후속 변경까지 소급하지 않는다. 이후 입력 보관과 UI 수정은 [운영 화면 재검토](./OPERATIONS_UI_UX_REVIEW_2026-08-31.md), 최신 피크 보존 수정과 검증 상태는 [제출 준비 기록](./SUBMISSION_REVIEW_2026-08-31.md)을 따른다.

후속 직접 검수에서 다섯 운영 화면을 포함한 일곱 화면의 대표 뷰포트, 두 설비의 발행·점검·종결 및 새로고침 복원을 확인했다. 아래 접근 제한은 최초 구현 당시의 기록이다. 최신 캡처와 확인 결과, 추가 반복 검사에서의 도구 제한은 [전 화면 직접 검수](./BROWSER_REVIEW_2026-08-31.md)를 따른다.

## 범위와 공개 상태

사이드바에서 미제공으로 표시하던 생산 분석, 이상 관리, 정비 관리, 알림, 설정을 구현했다. 다섯 개의 독립적인 목업이 아니라 기존 COATER-02 진단과 작업 지시를 중심으로 실제 상태가 이어지는 공개 데모다.

이 문서는 로컬 작업 트리의 구현 기록이다. 이번 작업에서 커밋, 푸시와 공개 배포는 수행하지 않았다. 외부 DB 계정 생성이나 유료 인프라 추가도 하지 않았다. 실제 설비, 실제 직원, 고객사의 생산 실적을 사용하지 않는다.

## 사용자 흐름

```text
이상 발생 알림 → 이상 확인과 담당자 지정 → 센서 진단과 안전 확인
                                           ↓
생산 분석의 처리 현황 ← 이상 종결 ← 점검 결과 기록 ← 작업 지시 발행
                            ↑              ↓
                     잔여 위험 확인     정비 관리에서 점검 시작
```

점검을 완료해도 이상을 자동으로 종결하지 않는다. 연결된 작업의 완료, 결과 확인과 종결 사유가 필요하다. 이상 종결은 브라우저의 업무 처리 기록이며 합성 센서가 정상으로 바뀌었다는 증거가 아니다.

## 제공 기능

| 화면 | 제공 기능 | 명시적인 한계 |
| --- | --- | --- |
| 생산 분석 | 완료된 최근 24시간/7일과 직전 동기간 비교, 라인 필터, 코팅 길이와 가중 불량률, 그래프/표, CSV | 14일의 합성 실적. 실제 MES, OEE, 수율 개선 효과가 아님 |
| 이상 관리 | 검색, 처리 상태/심각도 필터, 확인, 담당자 지정, 연결된 작업, 종결 사유, 처리 이력 | 현재 활성 합성 이상 하나와 완료 예시 두 건. 다른 설비의 상세 진단이나 임의 이상 등록은 없음 |
| 정비 관리 | 작업 검색과 상태/기한 경과 필터, 발행 정보, 시작, 점검 결과와 완료, 이상 연결 | 예방 정비 계획, 부품 재고, 작업 취소/재개방, 외부 작업 전송 없음 |
| 알림 | 발생/종결, 작업 발행/시작/완료, 기한 경과, 읽음 처리, 관련 기록 링크 | 앱 내부 알림. 이메일/OS 푸시 아님. 닫힌 앱에서 기한 확인을 실행하지 않음 |
| 설정 | 차트 기본 5/15/30분, KST/UTC, 새 알림 종류, 저장소 복구, JSON 내보내기, 확인 후 초기화 | 화면 환경설정. 설비 제어값, 실제 경보 기준, 인증/권한 설정 아님 |

작업의 `대기 → 진행 중 → 완료`와 이상의 `미확인 → 확인됨 → 조치 중 → 종결`을 별도 모델로 둔다. 진단에서 바로 발행하면 이상 확인 버튼을 거치지 않고 조치 중이 된다. 완료 예시는 목록에서 구분하며 사용자가 수행한 처리 실적에서 제외한다.

## 저장과 장애 대응

- 브라우저 IndexedDB의 버전 1 문서를 사용한다. 새로고침 후 미확인 요청, 작업, 이상 처리, 알림과 설정을 복원한다.
- 같은 출처의 브라우저 탭 사이에서만 공유한다. 각 변경은 최신 문서 읽기, 상태 전이 검사, 쓰기를 하나의 트랜잭션으로 처리하고 저장 완료 후에만 성공을 표시한다.
- BroadcastChannel은 다른 탭에 변경을 알리는 용도다. 데이터 기준은 IndexedDB다. 포커스 복귀 시에도 다시 읽는다.
- 작업 발행 요청을 먼저 저장한다. 서버 응답 후 작업, 이상 상태, 알림과 미확인 요청 해제를 함께 저장한다. 저장 실패나 응답 유실 시 같은 요청으로 재확인한다.
- 발행 결과가 불확실하면 담당자 변경과 초기화를 막는다. 초기화의 선행 조건은 화면뿐 아니라 DB 트랜잭션에서도 확인한다.
- 저장소 접근 거부, 타임아웃, 공간 부족과 손상 기록을 사용자에게 알린다. 형식을 확인할 수 없는 기존 데이터는 자동 덮어쓰기 하지 않는다.
- 저장 중에는 완료 안내를 기다리도록 표시하고, 아직 DB 쓰기가 남은 상태에서 페이지를 떠나면 `beforeunload` 경고를 요청한다. 경고 표시 여부는 브라우저 정책을 따르며, 저장 완료 전의 강제 종료까지 보장하지 않는다.
- 작업은 예시 포함 최대 100건, 이상은 최대 100건, 알림은 최근 200건, 개별 처리 이력은 최근 100건이다. 주석은 별도 탭 메모리에 최대 240자/최근 50건이며 새로고침 시 초기화된다.
- 데이터 내보내기는 열람용 JSON이다. 가져오기는 지원하지 않으며 서버 백업이 아니다. 초기화는 이 앱의 업무 문서와 해당 탭의 주석을 지우고 초기 예시를 다시 만든다.

저장 완료 안내가 나온 기록을 새로고침 후 복원한다. 사이트 데이터 삭제, 저장 공간 정리, 비공개 세션 종료로 데이터가 사라질 수 있다. 기기 간 동기화, 서버 권한, 변경 불가능한 감사 로그와 분산 exactly-once를 제공하지 않는다. 서버 발행 기록은 기존대로 인스턴스 메모리 범위다.

## 생산 지표의 의미

- 양품 판정 길이 = 검사 길이 합계 − 불량 판정 길이 합계
- 계획 대비 양품 달성률 = 양품 판정 길이 / 계획 길이 × 100
- 불량 판정 비율 = 불량 판정 길이 합계 / 검사 길이 합계 × 100
- 누적 정지 시간 = 선택한 각 라인의 정지 시간 합계. 여러 라인의 동시 정지를 한 번으로 합치는 벽시계 시간이 아님
- 7일 조회의 그래프와 표는 24시간 구간 단위이며 달력 날짜 또는 교대조 집계가 아님
- 분모가 없으면 0% 대신 값 없음으로 표시

센서 순간값과 생산 집계, 브라우저에서 사용자가 완료한 업무 건수는 서로 다른 데이터다. 점검을 완료했다고 합성 생산량이나 불량률을 변경하지 않는다. 사용자 점검 완료/이상 종결 건수는 현재 시각 기준 최근 24시간 또는 7일로 별도 계산한다.

## 검증 기록

신규 기능의 정상 흐름, 설정 복원, 다중 탭 변경, 요청 유실 복구, 저장소 접근 거부, 생산 조회 복구와 내보내기를 Chromium E2E로 확인했다. 다섯 화면 각각 1440/1024/700/390/320px에서 가로 넘침을 검사하고 1440/320px에서 axe-core WCAG A/AA 규칙을 검사했다. 신규 화면의 브라우저 제목이 비던 문제는 문자열 하나로 제목을 구성하도록 수정했다.

### 경계별 근거

| 경계 | 확인한 근거 |
| --- | --- |
| UI → API | 안전 확인 후 실제 발행 요청. 응답 유실과 저장 실패 뒤 요청 ID와 본문이 동일한 재시도인지 검사 |
| API → 합성 데이터 | 서버 생성기 672건의 기간/측정값 일관성과 같은 시간대 재시작 안정성, 생산 API 오류 후 재조회 |
| 업무 명령 → DB | 완료 전 종결 차단, 담당자와 활성 작업 동기화, 저장 실패 시 성공 화면 없음, 같은 브라우저 두 탭의 독립 변경 보존 |
| DB → UI | 새로고침 후 작업·설정·읽음 복원, 점검 완료 후 별도 이상 종결, 공정 개요와 생산 분석의 처리 현황 반영 |
| 오류 → 복구 | 저장소 접근 차단 후 재연결, 결과 저장 중 실패 후 동일 요청 복구, 빈 검색 결과 초기화, 잘못된 상세 링크의 명시적 빈 상태 |
| 보관 → 사용자 제어 | JSON/CSV 내려받기, 확인 문구 전 초기화 차단, 초기화가 업무 문서 밖의 localStorage 값을 지우지 않음 |

검증 중 테스트의 선택자를 실제 접근성 역할과 이름 기준으로 보정했다. 전체 읽음 직후 저장 완료 전에 새로고침하던 경합도 드러나, 회귀 검사는 저장 성공 안내를 확인한 뒤 복원을 검사하도록 했다. 제품에는 저장 중 안내와 미완료 쓰기의 이탈 경고를 추가했다. 별도로 저장 중 실패를 주입한 검사는 미확인 요청을 잃거나 거짓 성공을 표시하지 않는지 확인한다.

React 품질 검토 기준에 따라 신규 라우트를 비동기 청크로 분리하고 고빈도 센서 상태와 업무 저장 상태를 나눴다. 업무 흐름 검증 기준은 화면의 표시만이 아니라 요청, 저장 완료, 복원과 종결까지 확인하는 데 적용했다.

## 수동 검수와 운영 한계

최초 구현 당시 앱 브라우저 접근 정책으로 로컬 접근이 차단되어 다른 브라우저로 우회하지 않았다. 이후 같은 내장 브라우저에서 다섯 운영 화면의 대표 크기와 핵심 흐름을 직접 확인했다. 그 확인이나 자동 접근성 검사는 실제 화면 낭독기, Safari/Firefox, 현장 터치 패널과 제조 네트워크의 검증을 대신하지 않는다.

이번 구현은 제품 업무 흐름과 프론트엔드 상태 관리를 체험하는 공개 데모다. 실사용자 인터뷰, 실제 직원의 승인과 알림, 설비 안전 검증, 생산 효과의 인과 분석, 서버 운영 SLA는 포함하지 않는다.
