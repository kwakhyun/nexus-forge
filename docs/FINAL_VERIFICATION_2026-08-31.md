### 실패와 중단을 통과 기록에서 제외

전체 E2E 첫 실행은 55개 통과, 3개 실패였다. 진단 이력이 도착하기 전 기본 5초 기대 시간이 끝난 경우로, 한 이력 응답은 8.8초가 걸렸다. 원본 참고값이 준비된 상태를 기다린 뒤 화면과 조치 가능 여부를 검사하도록 보강했다.

두 번째 전체 실행은 11개 통과, 2개 실패, 2개 중단, 43개 미실행 상태에서 중지했다. 당시 로컬 시스템 부하가 높았고 Vite 모듈 응답도 5.9~6.4초 걸렸다. 이 실행을 전체 통과로 사용하지 않는다. 설비 재사용 검사에도 명시적인 로딩 완료 대기를 추가했고, 다중 경로 동선의 제한 시간을 60초로 정했다. 고정 sleep이나 기능 검사 삭제로 통과시키지 않았다.

최종 전체 회귀 결과는 독립된 GitHub 실행 환경에서 확인했다. 로컬 실행 시간은 성능 개선 근거로 사용하지 않는다. 이전 차트 및 앱 성능 수치는 [측정 당시 코드와 조건](./PERFORMANCE.md)을 유지하며 이번 UI 변경의 재측정값으로 바꾸지 않았다.

첫 [GitHub CI 실행](https://github.com/kwakhyun/nexus-forge/actions/runs/33356281684)은 성공 상태였지만 상세 로그에 `57 passed, 1 flaky`가 남았다. 설비 전환 직후 공통 이름의 검증 버튼을 눌러 이전 DRYER 대화상자를 다시 열었고, 새 경로가 반영되며 대화상자가 닫혀 기대한 COATER 안내가 없었다. 검사에 새 URL, 설비 제목과 해당 원본 참고값 확인을 넣어 의도한 대상의 버튼을 누르도록 보강했다. 다른 설비의 발행 차단, 요청 수와 동일 본문 재시도 기대값은 유지했다. 앞으로 CI에서는 `failOnFlakyTests`를 켜 재시도 후 통과도 배포 성공 조건으로 사용하지 않는다.

보강 후 설비 재사용 검사 3개를 각각 3회 반복해 9회 모두 통과했다. 한 워커, 재시도 0회 조건에서 약 2분 6초가 걸렸다. 명령은 `npm --workspace @nexus/web run test:e2e -- e2e/equipment-reuse.spec.ts --workers=1 --repeat-each=3 --retries=0`이다.

이 표는 구현과 검사 코드의 검증 스냅샷이다. 이후 문서만 바뀐 커밋에도 같은 CI와 배포 검사가 적용된다. 현재 공개 SHA는 [상태 API](https://nexus-forge-ten.vercel.app/api/health)에서 조회할 수 있다. 이전 `0aacc14`의 재시도 포함 실행과 이 최종 결과는 혼합하지 않는다.

오류 조회는 해당 배포와 짧은 시간 구간에 한정한다. 로그 수집의 완전성, 상시 모니터링이나 서비스 SLA를 검증한 것은 아니다. 이번 작업에서 외부 로그 전달(Drains), 유료 모니터링과 상시 알림을 새로 구성하지 않았다.

[공개 배포 검증 스크립트](../scripts/verify-production.mjs)는 요청마다 15초 제한을 두고 다음을 확인한다.

1. `/api/health`의 release SHA와 배포 대상 커밋 일치
2. 8개 UI 경로의 HTML 셸 응답
3. 두 설비가 포함된 공정 요약, 두 생산 라인의 합성 실적
4. COATER-02와 DRYER-02 각각의 10,000개 이상 이력 및 설비 ID
5. 두 설비를 별도로 구독한 WebSocket 프레임의 ID와 유한한 센서 값

이 검사는 HTML 셸만으로 Canvas 렌더링까지 검증했다고 주장하지 않는다. 렌더링과 업무 흐름은 로컬/CI Playwright 및 앞선 직접 화면 검수의 별도 근거를 따른다.

## 검증 범위와 운영 한계

이번 완료 범위는 공개 데모의 구현 수정, 대표 화면 및 핵심 흐름 검증, 회귀 검사와 문서 정리, 커밋에 일치하는 자동 배포다. 실제 제조 운영 전환을 뜻하지 않는다.

Safari/Firefox, 실제 화면 낭독기, 실기기 터치, 현장 네트워크, 실제 설비 프로토콜, 다중 사용자 승인과 교대 시간 규모의 장기 부하는 별도의 확장 검증이다. 합성 데이터, 브라우저 전용 저장과 서버 발행 기록의 비영속성도 유지한다. Storybook의 개발 문서용 큰 청크 경고와 테스트 서버 종료 시 프록시 로그는 무시된 기능 실패와 구분한다. 모든 환경에서 무결함이나 전체 접근성 준수를 보증하지 않는다.
