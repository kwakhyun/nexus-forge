# 성능 전략

## 실측 결과

2026년 8월 30일 Apple M2, Node.js 22.21.0, Chromium 151 환경에서 측정했습니다. 차트 측정은 1200×700, DPR 1, 애니메이션 비활성화, ECharts Canvas 4개 패널과 6개 시리즈 조건으로 각 시나리오를 한 차례 예열한 뒤 9회 반복했습니다.

| 측정 항목 | 기준 구현 | 현재 구현 | 변화 |
| --- | ---: | ---: | ---: |
| ECharts 전용 번들, minified | 1,132.1KB | 589.9KB | 47.9% 감소 |
| ECharts 전용 번들, gzip | 380.2KB | 199.5KB | 47.5% 감소 |
| Canvas 렌더 중앙값 | 18,000개 시점 32.6ms | 1,800개 시점 6.7ms | 79.4% 감소 |
| Canvas 렌더 p95 | 35.6ms | 16.5ms | 53.7% 감소 |

번들 비교는 전체 `echarts` 패키지를 가져오는 방식과 현재 화면이 사용하는 Core 모듈만 가져오는 방식을 동일한 Vite minify와 gzip 조건에서 각각 빌드한 결과입니다. 렌더 비교는 같은 합성 시계열에서 원본 18,000개 시점과 변화량 기반으로 선택한 1,800개 시점을 같은 차트 옵션에 전달한 결과입니다. 옵션은 다섯 개 센서 시리즈와 온도 설정값, 연결 커서, 내부 확대·축소, 이상 영역과 이벤트 기준선을 포함해 실제 진단 화면의 렌더링 범위를 반영합니다.

렌더 시간은 `setOption` 호출부터 zrender `flush` 완료까지의 동기 구간입니다. 데이터 생성과 다운샘플링 계산, 네트워크 전송은 측정에서 제외해 차트에 전달하는 시점 수의 영향만 비교했습니다.

```bash
npm run benchmark:performance
```

스크립트는 측정 시각, 운영체제, CPU, Node.js와 Chromium 버전, 반복 횟수, 차트 범위, 중앙값과 p95를 JSON으로 출력합니다. 이 문서의 표는 [2026년 8월 30일 원본 결과](./benchmarks/performance-2026-08-30.json)를 고정한 스냅샷입니다. 결과는 장비와 브라우저 상태에 따라 달라지는 로컬 합성 벤치마크이므로 현장 SLA나 사용자 성능 개선율로 일반화하지 않습니다.

## 목표

- 초기 공정 개요는 진단 차트 코드를 내려받지 않습니다.
- 실시간 데이터 반영은 초당 4회 수신을 500ms 배치로 묶어 초당 2회 렌더링합니다.
- 메모리에 보관하는 시점은 최대 20,000개로 제한합니다.
- 차트에는 최대 1,800개 시점만 전달하되 경계와 급격한 이상값은 유지합니다.
- 차트 애니메이션을 끄고 Canvas 렌더러를 사용합니다.

## 적용한 최적화

### 라우트와 서드파티 지연 로딩

진단 라우트는 `React.lazy`로 분리했습니다. ECharts는 공정 개요 진입 시 로드되지 않습니다. Sentry도 DSN이 설정된 환경에서만 동적으로 가져옵니다.

### 트리 셰이킹 가능한 ECharts 구성

전체 ECharts 번들 대신 LineChart와 Grid, Tooltip, DataZoom, MarkArea, MarkLine, CanvasRenderer 등 화면에 필요한 모듈만 등록했습니다.

격리된 번들 벤치마크에서 minified 크기는 1,132.1KB에서 589.9KB로, gzip 크기는 380.2KB에서 199.5KB로 감소했습니다.

### 고정 용량 스트림 버퍼

배열 앞부분을 반복해서 제거하지 않고 순환 인덱스로 오래된 값을 덮습니다. 장시간 실행해도 저장되는 센서 시점 수가 상한을 넘지 않습니다.

### 동기화 다운샘플링

각 센서를 따로 샘플링하면 서로 다른 시점이 선택되어 상관관계가 왜곡될 수 있습니다. NEXUS Forge는 한 시점의 다섯 신호 변화량을 합산해 대표 시점을 선택하므로 모든 패널이 같은 타임스탬프를 유지합니다.

## 진단 방법

- 빌드 청크 크기를 CI 로그에서 확인합니다.
- 차트 툴바에 원본 버퍼 시점 수와 Canvas 렌더러를 표시합니다.
- 단위 테스트가 포인트 예산, 시간 경계, 이상값 보존을 검증합니다.
- 브라우저 검증에서 페이지 오류, 콘솔 경고, 핵심 동작을 함께 확인합니다.

## 실제 연동 시 추가할 항목

- PerformanceObserver 기반 INP, Long Task, 프레임 드롭 측정
- 시계열 압축 또는 서버 측 멀티해상도 집계
- SharedWorker를 통한 탭 간 스트림 공유
- OffscreenCanvas와 Web Worker 기반 전처리
- 장비 수 증가에 따른 구독 채널 분리와 백프레셔 정책
