# 성능 전략

## 목표

- 초기 공정 개요는 진단 차트 코드를 내려받지 않습니다.
- 실시간 데이터 반영은 초당 4회 수신을 500ms 배치로 묶어 초당 2회 렌더링합니다.
- 메모리에 보관하는 시점은 최대 20,000개로 제한합니다.
- 차트에는 최대 1,800개 시점만 전달하되 경계와 급격한 이상값은 유지합니다.
- 차트 애니메이션을 끄고 Canvas 렌더러를 사용합니다.

## 적용한 최적화

### 라우트와 서드파티 지연 로딩

진단 라우트는 `React.lazy`로 분리했습니다. ECharts는 공정 개요 진입 시 로드되지 않습니다. Sentry도 DSN이 설정된 환경에서만 동적으로 가져옵니다.

### 트리 셰이킹 가능한 ECharts 구성

전체 ECharts 번들 대신 LineChart와 Grid, Tooltip, DataZoom, MarkArea, MarkLine, CanvasRenderer만 등록했습니다. 이 변경으로 차트 청크의 압축 전 크기를 약 1.13MB에서 약 557KB로 줄였습니다.

### 고정 용량 스트림 버퍼

배열 앞부분을 반복해서 제거하지 않고 순환 인덱스로 오래된 값을 덮습니다. 장시간 실행해도 저장되는 센서 시점 수가 상한을 넘지 않습니다.

### 동기화 다운샘플링

각 센서를 따로 샘플링하면 서로 다른 시점이 선택되어 상관관계가 왜곡될 수 있습니다. NEXUS Forge는 한 시점의 다섯 신호 변화량을 합산해 대표 시점을 선택하므로 모든 패널이 같은 타임스탬프를 유지합니다.

## 진단 방법

- 빌드 청크 크기를 CI 로그에서 확인합니다.
- 차트 툴바에 원본 버퍼 시점 수와 Canvas 렌더러를 표시합니다.
- 단위 테스트가 포인트 예산, 시간 경계, 이상값 보존을 검증합니다.
- 브라우저 검증에서 페이지 오류, 콘솔 경고, 핵심 동작을 함께 확인합니다.

## 실제 연동 시 추가할 항목

- PerformanceObserver 기반 INP, Long Task, 프레임 드롭 측정
- 시계열 압축 또는 서버 측 멀티해상도 집계
- SharedWorker를 통한 탭 간 스트림 공유
- OffscreenCanvas와 Web Worker 기반 전처리
- 장비 수 증가에 따른 구독 채널 분리와 백프레셔 정책
