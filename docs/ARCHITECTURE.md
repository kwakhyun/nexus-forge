# 아키텍처

## 구성

```text
브라우저
  ├─ React UI
  ├─ TanStack Query ── HTTP API ──┐
  └─ Zustand + RingBuffer ─ WebSocket ─┤
                                      │
                               stream-server
                                      │
                         합성 설비/센서 시뮬레이션
```

```text
apps/
  web/             운영 화면, 차트, 테스트, Storybook
  stream-server/   REST API, WebSocket, 결정론적 센서 시뮬레이션
packages/
  contracts/       API와 스트림의 공유 TypeScript 계약
  ui/              토큰과 재사용 UI 프리미티브
```

Turborepo가 패키지 빌드 순서와 캐시를 관리합니다. 웹과 서버는 `@nexus/contracts`를 공유하므로 센서 또는 작업 지시 스키마가 달라질 때 컴파일 단계에서 불일치를 확인할 수 있습니다.

## 상태 경계

- TanStack Query: 공정 요약, 30분 이력, 작업 지시 생성처럼 서버가 소유하는 비동기 상태
- Zustand: 스트림 연결 상태, 고빈도 센서 스냅샷, 역할 선택, 다이얼로그 상태
- 컴포넌트 로컬 상태: 체크리스트 입력처럼 해당 인터랙션에만 필요한 상태

이 구분으로 서버 캐시와 프레젠테이션 상태가 섞이지 않으며, 스트림 갱신이 불필요한 전체 화면 렌더링으로 퍼지는 것을 줄였습니다.

## 데이터 흐름

1. 진단 화면은 REST API에서 30분 이력 18,000개 시점을 가져옵니다.
2. 이력은 고정 용량 20,000개의 링 버퍼에 들어갑니다.
3. WebSocket은 250ms 간격으로 새 시점을 전송합니다.
4. 클라이언트는 수신값을 500ms 단위로 모아 한 번에 상태에 반영합니다.
5. 변화량 기반 다운샘플러가 1,800개 대표 시점을 선택합니다.
6. ECharts Canvas 렌더러가 네 개의 동기화 패널과 다섯 개 신호를 그립니다.

## 장애 대응

- 스트림 종료 시 지수 백오프로 최대 10초 간격까지 재연결합니다.
- 소켓 연결 여부와 센서 신선도를 분리합니다. 센서 값이 5초 넘게 끊기면 지연 상태로 전환하고, 하트비트를 포함한 전체 프레임이 35초 넘게 끊기면 연결을 강제로 다시 맺습니다.
- 연결 중, 센서 지연, 재연결 중, 오프라인, 정상 상태를 헤더에 명시합니다.
- 공정 요약 실패는 라우트 수준 오류 화면으로 전환합니다. 30분 이력 실패는 차트 안에서 재시도할 수 있게 하고, 복구 전에는 원인 신뢰도를 숨기며 현장 검증 발행을 차단합니다.
- 현장 검증 요청 실패는 다이얼로그 안에서 재시도 가능한 오류로 표시합니다.
- `VITE_SENTRY_DSN`이 있을 때만 Sentry를 동적으로 로드합니다.

## 공개 데모 배포 경계

Vercel의 Production target을 공개 포트폴리오 데모의 배포 환경으로 사용합니다. `dist/client`의 정적 자산은 CDN으로 제공하고, REST API와 WebSocket 스트림은 동일 저장소의 Vercel Functions로 배포합니다. Functions와 로컬 Node 서버는 같은 요청 처리 및 센서 시뮬레이션 모듈을 사용하므로 실행 환경에 따른 계약 차이를 줄였습니다. 이 구성은 실제 제조 고객사의 상용 운영 환경을 의미하지 않습니다.

Vercel의 Git 푸시 직접 배포는 `vercel.json`에서 끕니다. `main`에 푸시하면 GitHub Actions가 lint, typecheck, 단위 및 컴포넌트 테스트, 빌드, Storybook과 Chromium E2E를 병렬 검증합니다. 두 작업이 모두 성공한 뒤에만 암호화된 Vercel 배포 훅을 호출합니다. 배포가 끝나면 공개 `/api/health`의 `release`가 해당 GitHub 커밋 SHA와 일치하는지 확인하고, UI 셸, 공정 요약, 센서 이력, WebSocket 수신까지 스모크 테스트합니다. 빌드 성공과 공개 승격 사이의 검증 순서를 명시적으로 고정한 구성입니다.

클라이언트는 Functions 재시작과 배포 교체에 대비해 WebSocket 연결을 지수 백오프로 다시 맺습니다. 현재 작업 지시 기록은 데모 범위의 런타임 메모리에 보관되며, 다중 인스턴스 환경의 영속 상태는 Redis 또는 관계형 데이터베이스로 이전하는 것이 다음 단계입니다.

로컬 통합 서버의 `/health`는 같은 프로세스에 연결된 WebSocket 클라이언트 수를 반환합니다. Vercel에서는 REST와 스트림 Function의 인스턴스가 분리되고 전역 접속 상태 저장소가 없으므로 `clients: null`과 `clientCountScope: "unavailable"`을 반환해 `0명 접속`으로 오해하지 않도록 했습니다.

ChatGPT Sites용 정적 산출물은 보조 배포 호환성을 위해 계속 생성합니다. 실제 온프레미스 환경에서는 리버스 프록시가 `/api`와 `/stream`을 같은 출처로 노출하는 구조가 적합합니다.
